# Plug-in Panels layout builder

A web page for writing layouts for Framework: Plug-in Panels. It reads a plug-in's parameter sheet, lets you build the panel with a live preview, and saves the layout JSON the framework loads. It is plain HTML, CSS and JavaScript: no build step, no server, nothing loaded from elsewhere. The preview approximates Bitwig's look with CSS; it uses none of Bitwig's files.

## Open it

Open `index.html` in a browser (Chrome, Edge, Firefox or Safari), from disk or from any web host. Your work is kept in the browser between visits.

## Use it

1. **Parameter sheet.** In Bitwig, right-click the plug-in and choose **Generate Parameter Sheet**. It copies the sheet and saves it as `<plug-in> <format>.parameters.json` in the `sheets` folder of the framework's folder in Patchbay's settings folder. Drop the file on the page, or press **Paste…** (or Ctrl+V on the page).
2. **Check each parameter in Bitwig.** The sheet gives each parameter's texts at 0 and 1; whether its text follows the value at once, and whether typed values work, is for you to check. The parameter list shows what the sheet suggests, and nothing is applied unless you click it:
   - **text unreliable**: the texts at 0 and 1 are the same, so the plug-in's text can't be trusted (ValhallaVintageVerb). `"refresh": "settle"` and a `values` mapping usually help.
   - **whole numbers**: a continuous parameter whose texts are whole numbers (Rift's Positive Type, 0 to 29): a dropdown with one choice per number, or a stepped knob.
   - **toggle?**: the ends are exactly 0 and 1, or Off and On (TAL-Chorus-LX's Chorus 1).
   - **min…max unit**: the ends read as numbers in one unit. A knob added from the list gets them as a prefilled `values` mapping to confirm. When the current value's text fits a log curve better than a linear one, the hint says so.
3. **Build.** Click a parameter to open it and add a control, or drag it onto the outline or the preview. Controls go side by side in a row: after the selected one, or at the end of the current row; **Add › Row** starts the next row, **Add › Column** a column beside. Each control is a cell of the same width (54), knobs one size (34, a fixed cell: label, knob and value centred, a longer text never widening it), as VintageVerb's layout does; these values are written into the JSON, so Bitwig draws what you see, and every one can be changed. On a row, **Same knob size** and **Equal widths** even out its items. **Add › Spacer** puts empty space in the column, after the selected row (an empty row selected becomes the spacer), where it takes the column's spare height (with `fill_height`, or beside a taller column): Volume at the top, a spacer, Stereo at the bottom. With an item selected in a row that has a `width`, or in the footer, it goes into that row and takes its spare width instead. The preview draws it faint and dashed; the inspector says which way it grows and how much it takes, and moves a spacer out of a row into its column (**Move to column**). Select anything in the outline or the preview to edit it in the inspector, which offers every key the schema has for it. Drag in the outline to reorder or move. Keys: Delete, Ctrl+D (duplicate), Alt+↑/↓ (move), Ctrl+Z / Ctrl+Y.
   **Lining things up.** With **guides** on (in Show, off by default), the selected item's edges are drawn as faint lines across the panel (a hovered item's dashed), and their heights in layout units from the device's top are listed beside the device, right of the height zones, never over the panel: for a knob its top, label top, ring top (the arc's outer edge, from the framework's knob geometry), ring centre and value top; for other controls their top, centre and bottom. **Align top / centre / bottom with…** in the inspector lines an edge of the selected item (any of its edges) up with an edge of another item, e.g. a toggle's top with Volume's ring top, or its bottom with Stereo's value bottom. It moves the item from the side it sits from: top padding for an item stacked from the top, bottom padding for one pushed down by a spacer (or `valign` bottom); the padding goes on its row, on its column when it's the column's first or last item, or on a row of its own. To take an item's bottom further down in a `fill_height` column, it puts a spacer above it first, so it stays at the bottom. Padding is whole units; the inspector says what it will use and how far off that leaves it, and refuses a move the room doesn't allow (e.g. more than its spacer's spare height): then align the other item to it. While you pick, the two edges show as guides even with guides off, until you apply or select something else. A label line's height comes from its font, not from the knob's size.
4. **Check.** The Problems tab lists what the framework would refuse (errors: Bitwig's own page is shown instead), ignore or leave out (warnings), and what the preview can't show (info). With the sheet loaded, every parameter reference is resolved as the framework resolves it. **Available height** takes the figure from Bitwig's log (`height available N units`) and draws it on the preview.
5. **Save.** **Copy JSON** copies the panel; in Bitwig, right-click the plug-in and choose **Save Panel from Clipboard** to save it in Patchbay's `components/` folder. **Download** saves the same file (named after the panel's name, else the plug-in), to put in `components/` yourself. Choose the panel in Patchbay, then start Bitwig again. **panel name** (at the top of the layout's settings) is the name Patchbay lists it by.

**Open…** also reads an existing layout to edit, including a file with `{"layouts": [...]}`. Keys the builder doesn't change keep their values and their order, so opening a layout and saving it gives the same layout back. The JSON tab shows the file as it will be saved and can be edited directly (**Apply edited JSON**).

The layout format itself is described in the framework's README (`../README.md`).

## Check the round trip

With Node.js, `node test/roundtrip.js <files>` reads each layout, checks it (against a parameter sheet given in the same call, when it matches), writes it again and reports whether the written JSON reads the same and keeps its key order. For a parameter sheet, it prints the hints per parameter.

## The preview

The preview builds the same boxes the framework builds, by the same rules and constants (`preview.js` names the framework method each part follows): padding, gaps, dividers in the middle of their gap, header lines on every column of a page, fixed widths, knob cells and their equal shares of a row, the row aligner for knobs of theme size, backgrounds with their 2-unit padding, the footer, and only the shown page taking space. Envelopes are drawn as the framework draws them: segment widths from the normalised values or the times (linear or log), the held level a fifth of the width, the sustain level, the dots and the display colours (120 × 50 by default). It is drawn at Bitwig's UI scale (**UI scale**, 150% by default) and reports the height the framework logs (`needs N units high (layout alone M)`).

**Default theme.** The builder draws with Bitwig 6.1.4's default theme at UI scale 150% (`default-theme.js`), so names, fonts, colours, knob sizes and spacing are Bitwig's own. It is always the starting point: **Start over** clears the layout, the parameter sheet and the overlay and returns to it; **New** starts a new layout and keeps the parameters and the theme.

**BTE themes.** For a theme made with Berikai's Bitwig Theme Editor (as Patchbay's Framework: Themes uses them), drop its `.bte` file on the page, open it, or paste its text. It is read as Framework: Themes reads it (`Name: #rgb | #rgba | #rrggbb | #rrggbbaa`, `Gradient: true | false`) and recolours the default theme by Bitwig's colour names: the colour table, the knob styles (Knob Body, Knob Stroke, Knob Value Background, Knob Value Color, Knob Line and their variants), the envelope display (Display Background, Display Waveform), the device header, and a label's default text. Names outside Bitwig's colour table (the EQ and Note FX keys, misspellings) are listed in the theme's tooltip and not used; `Gradient: false` draws knob bodies flat. Fonts, knob sizes and spacing aren't in a `.bte` and stay the default theme's. The theme stays with your work, also after a reload, until **Start over** or its ×.

Without `default-theme.js`, the builder falls back to `theme.js`'s own values, each marked with its source: measured in Bitwig, read from Bitwig's theme file, or approximate. Dropdown heights aren't in the theme: they stay approximate unless an item gives its `height`. The panel text is set in Lato, the typeface Bitwig ships; with Lato installed, text widths match Bitwig's. **Overlay…** puts a Bitwig screenshot over the preview to compare them; take it at the same UI scale.

**After a Bitwig update** (maintainers): in Bitwig with its default theme (no BTE theme active), right-click a plug-in and choose **Generate Theme Sheet** (shown in Debug Mode), then run `node tools/make-default-theme.js <theme.sheet.json>` to regenerate `default-theme.js`. To check a sheet first, open `index.html?dev` and drop it: it is drawn over the default theme for that visit only.

## Limits

- A BTE theme changes colours only, and the builder doesn't recreate the shades Bitwig derives from a colour (its lighter and darker variants); a knob body or track a BTE theme sets is drawn as given. Dropdown heights and the toolbar row are the builder's own. Bitwig's icons show as placeholders, and colours the builder doesn't know are hatched.
- One layout is edited at a time; a file with several layouts is edited one by one (the picker in the top bar).
